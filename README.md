# Godot_fps-OL
这是一个godot的多人联机fps项目
本项目是我个人在移动端与 PC 端混合环境下，基于 https://github.com/Droivox/Godot-Engine-FPS 的素材从零开始搭建的联机 FPS 原型。它实现了基础的房间联机、实时同步、射击反馈、个人竞技等核心玩法，旨在探索 Godot 引擎在多人射击游戏领域的可行性。

以下是当前版本存在的主要问题：

# 🔴 代码质量
历史遗留严重：项目经历了多次“重构”与“堆砌”，部分模块（尤其是网络同步、玩家控制器）存在冗余、硬编码（尤其是武器）和逻辑混乱。

命名不规范：变量、函数、文件命名风格不统一，部分为中文拼音或随意缩写，可读性较差。

脚本耦合度高：大量逻辑集中在少数巨型脚本中（如 GaemRoomif.gd（拼写错误）、character_body_3d.gd），难以维护和扩展。

无效脚本：例如Network.gd

GaemRoomif.gd大量使用AI生成的代码，character_body_3d.gd的聊天扩展部分使用AI生成的代码

缺少注释与文档：核心逻辑缺少说明，新接入者理解成本较高。

# 🔴 网络与同步
房主权威模式：当前采用经典的房主-客户端模式，房主承担全部游戏逻辑（伤害计算、状态广播），对房主的网络和性能要求较高，且存在单点故障风险。

缺乏防作弊机制：客户端上报命中信息，房主虽做二次验证，但基础框架未做深度防护，恶意客户端可伪造数据。

NAT穿透未实现：目前仅支持局域网或公网直连（需端口转发），未集成 STUN/TURN 或任何中继服务，无法直接用于互联网环境。

# 🔴 资源与美术
临时/占位资源：大部分模型、贴图、音效为临时占位，来源不一（包括解包测试），存在版权风险，需全部替换为自有或开源合规资源。

场景粗糙：测试地图简陋，缺乏完整的游戏场景与视觉效果。（虽然后面做了新的地图，但是已经成了废案）

UI/UX 不完善：界面仅满足基础功能，交互反馈和美观度不足。

# 🔴 游戏机制
武器系统单薄：仅实现两种枪械的射击与换弹，缺少后坐力、散射、配件等深度机制。

模式单一：仅包含个人竞技基础框架，未完善回合制、比分结算、重生点管理等。

角色表现不足：角色模型为简易胶囊体（后来跟换了简易模型），无骨骼动画、第一人称手臂与第三人称身体分离逻辑未完整实现。

# ✨ 已实现功能
☑ 基于 UDP 的点对点（P2P）联机架构（房主-客户端）
☑ 玩家位置、旋转、动画状态实时同步
☑ 基础射击（射线检测）与弹孔同步
☑ 两种武器（维克托、格洛克17）切换与开火
☑ 团队竞技模式（红蓝阵营分配、伤害判定、比分统计）
☑ 血量系统与死亡重生
☑ 聊天系统
☑ 枪声、换弹音效播放
☑ 基础移动控制（WASD / 触屏十字键）
